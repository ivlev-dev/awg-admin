# Worker — AmneziaWG node agent

Воркер — единственный компонент, который трогает `amneziawg` и `tc` на сервере.
Он подключается к админке исходящим gRPC-стримом, поэтому открытых портов не требует.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AWG_GRPC_URL` | `http://127.0.0.1:9090` | gRPC-адрес админки |
| `AWG_GRPC_TLS_CA` | — | PEM CA для проверки admin; включает TLS |
| `AWG_GRPC_TLS_DOMAIN` | host из URL | SNI/имя сервера; включает TLS (system roots) |
| `AWG_GRPC_TLS_SYSTEM_ROOTS` | `false` | доверять системным корням; включает TLS |
| `AWG_GRPC_TLS_CLIENT_CERT` | — | PEM клиентский сертификат воркера (mTLS); только вместе с ключом и CA |
| `AWG_GRPC_TLS_CLIENT_KEY` | — | PEM ключ клиентского сертификата (mTLS) |
| `AWG_NODE_ID` | — | UUID ноды из админки (обязателен) |
| `AWG_NODE_TOKEN` | — | токен ноды, выдаётся один раз при создании (обязателен) |
| `AWG_DRY_RUN` | `false` | только логировать команды, ничего не применять; `1/true/yes/on` или `0/false/no/off`, иное значение — ошибка старта |
| `AWG_COUNTERS_PATH` | `/var/lib/awg-worker/counters.json` | локальный снапшот счётчиков |
| `AWG_PSK_STATE_PATH` | рядом с `AWG_COUNTERS_PATH` (`applied-psks.json`) | хэши применённых PSK; каталог тот же, что у счётчиков |
| `AWG_STATS_INTERVAL_SECS` | `2` | период опроса статистики |
| `RUST_LOG` | `info` | уровень логирования |

Если `AWG_DRY_RUN` включён, а `AWG_GRPC_URL` указывает не на loopback, воркер
пишет предупреждение: dataplane не меняется, но токен и статистика ноды всё
равно уходят на удалённую админку.

## TLS и mTLS

По умолчанию канал plaintext (h2c). TLS включается на воркере, если задан
`AWG_GRPC_TLS_CA`, `AWG_GRPC_TLS_DOMAIN` или `AWG_GRPC_TLS_SYSTEM_ROOTS=true`;
при этом воркер проверяет сертификат admin. Для взаимной аутентификации
дополнительно задаются `AWG_GRPC_TLS_CLIENT_CERT` и `AWG_GRPC_TLS_CLIENT_KEY`:
воркер предъявляет клиентский сертификат, подписанный CA из
`AWG_GRPC_TLS_CLIENT_CA` на стороне admin.

Правила валидации при старте:

- client cert и ключ задаются только вместе;
- client cert/ключ допустимы только при включённом TLS (CA/DOMAIN/SYSTEM_ROOTS) —
  иначе процесс завершается с ошибкой, так как mTLS без проверки сервера
  бессмыслен и небезопасен;
- файлы читаются при старте, PEM проверяется до подключения;
- без client cert/ключа поведение прежнее — server-auth TLS либо plaintext.

Выпуск CA и сертификатов, ротация и ограничения описаны в `OPERATIONS.md`,
раздел 9.1. Клиентский сертификат не заменяет `AWG_NODE_TOKEN`: токен
по-прежнему проверяется в `Hello`, mTLS лишь отсекает подключения без
доверенного клиентского сертификата на уровне TLS.

Fail-closed для plaintext реализован на стороне admin: в production admin не
стартует, если `AWG_GRPC_BIND` не loopback и TLS не настроен. Worker сам не
анализирует `AWG_GRPC_URL` и не отказывается подключаться по plaintext к
удалённому адресу — это остаточный риск, TLS для канала вне доверенной сети
нужно включать явно.

## Протокол сессии

1. Воркер открывает `WorkerGateway.Session` и отправляет первым сообщением `Hello { node_id, token, version }`.
2. Админка проверяет токен (sha256-хеш в БД), регистрирует сессию и отправляет `DesiredState`.
3. Воркер применяет состояние и отправляет `ApplyResult { revision, ok, error }`.
4. Каждые `AWG_STATS_INTERVAL_SECS` секунд отправляется `StatsSnapshot`:
   `interface_id`, `peer.device_id`, монотонные `rx_total`/`tx_total`, `last_handshake`.
   Поле `revision` — **применённая** ревизия, а не последняя полученная: если
   применение упало, статистика продолжает идти по предыдущему состоянию.
5. Админка шлёт `Ping` каждые 20 секунд; воркер отвечает `Heartbeat` с текущим
   временем (отдельного `Pong` в proto нет), поэтому админка видит живость даже
   при молчащем state-канале.

`ApplyResult` и ответ на `Ping` идут по отдельному control-каналу с приоритетом
над `StatsSnapshot`, поэтому не ждут очереди из 32 сообщений статистики.
Клиент gRPC принимает и отправляет сообщения до 64 MiB — большой `DesiredState`
не рвёт сессию.

При ошибке ревизия не запоминается: следующий цикл (в том числе после переподключения)
повторит применение. Если непустая `revision` совпадает с успешно применённой,
состояние повторно не применяется (debug в лог), это защита от лишнего churn.
Пустая `revision` трактуется как «ревизия неизвестна» и применяется каждый раз:
админка, которая пока не генерирует ревизии, не должна терять изменения после
первого apply. Успешное применение пустой ревизии сбрасывает запомненную.

Переподключение использует экспоненциальный backoff 1→60 с с jitter (±20%),
а не фиксированные 3 с. `connect_timeout` — 10 с, HTTP/2 keep-alive — 20 с,
таймаут запроса — 60 с.

При изменении сущностей админка пересобирает снапшот и пушит его в активную сессию ноды.

## DesiredState

Для каждого интерфейса передаются:

- `private_key`, `listen_port`, `mtu`, `addresses` (шлюзы пулов);
- обфускация: `H1..H4` (диапазоны), `S1..S4`, `HeaderProtectionKey`, `RandomTrailers`;
- пиры: `public_key`, `preshared_key`, `allowed_ips` (/32), `addresses` (CIDR пула), лимиты;
- `user_limits` — тарифные лимиты группы устройств пользователя;
- `forwarding` — разрешённые пары устройств (по IP).

## Применение

**AmneziaWG.** Интерфейс создаётся через `ip link add … type amneziawg` (если отсутствует),
адреса — `ip addr replace`, затем параметры и пиры — generic netlink
(`netlink-packet-amnezia-wireguard`, команда `SetDevice`).

Пиры применяются инкрементально, без `REPLACE_PEERS`: воркер читает dump,
добавляет отсутствующих, удаляет лишних (`WGPEER_F_REMOVE_ME`) и обновляет
изменившихся (`WGPEER_F_REPLACE_ALLOWEDIPS`). Неизменившиеся пиры в сообщение
не попадают, поэтому ядро сохраняет их endpoint'ы и handshake; PATCH лимитов
или forwarding больше не вызывает обрыва трафика.

**PSK.** Ядро не отдаёт PSK в dump, поэтому воркер хранит карту
`"<ifname>|<public_key>" → sha256(PSK)` в `AWG_PSK_STATE_PATH` (атомарная запись
tmp + `fsync` + rename, сам PSK на диск и в логи не попадает). Карта читается
при старте, поэтому ротация и снятие PSK, сделанные пока воркер был выключен,
применяются на первом же reconcile. При снятии PSK в `SetDevice` отправляется
явный нулевой ключ `[0u8; 32]`: отсутствие атрибута означало бы «оставить как
есть», и старый ключ остался бы в ядре. Ограничение: если файла состояния ещё
нет (первый запуск после обновления), прежние PSK неизвестны и не трогаются до
первого изменения `allowed_ips` или PSK.

**Адреса.** `ip addr replace` добавляет недостающие адреса, а адреса, которых
больше нет в desired state, удаляются. Link-local (`fe80::/10`, `169.254/16`)
не трогаются.

**Orphan-интерфейсы.** На первом apply после старта воркер перечисляет
существующие `amneziawg`-интерфейсы (`ip -o -d link show type amneziawg`) и
удаляет те, которых нет в desired state среди **enabled**-интерфейсов
(disabled-интерфейсы также удаляются — это согласуется с обычным reconcile;
в dry-run — только логи). Это убирает интерфейсы, осиротевшие после удаления
ноды/сети в админке и после выключения интерфейса.

**Teardown.** Сначала `ip link del`, затем `tc clear`, затем `nft clear`.
Если `ip link del` упал, имя остаётся в списке известных и повторяется с
экспоненциальным backoff (1→60 с) на следующих циклах; ошибка попадает в
`ApplyResult`. Если интерфейс уже удалён, teardown считается успешным
(идемпотентность).

**Graceful shutdown.** SIGTERM/SIGINT останавливают приём новых состояний,
дают текущему apply завершиться, отправляют финальный `ApplyResult` (best effort)
и джойнят stats/heartbeat-задачи; второй сигнал завершает процесс немедленно.

**tc.**

- egress: `htb` на интерфейсе, класс `1:1` (явная ёмкость линка или сумма
  лимитов пользователей), пользовательские классы `1:100+i`, классы устройств
  `1:1000 + i*1000 + per-user-index`, фильтры `u32 match ip dst`.
- ingress: `ingress` qdisc → `mirred` в `ifb-<hash>`, на IFB те же HTB-классы и фильтры `match ip src`.

Канонический список пользователей (сортировка + дедупликация, включая
`user_limits` и `user_id` пиров) строится один раз и используется и для классов,
и для фильтров, и для root rate — расхождение индексов невозможно. Индекс
устройства считается **внутри пользователя**, поэтому 100+ пиров не
пересекаются по classid; stride 1000 допускает до 64 пользователей по 1000
пиров (при превышении apply возвращает ошибку, а не молча усекает).

Root rate: если у пользователя лимит `0` («безлимит»), корневой класс получает
явную ёмкость линка `LINK_CAPACITY_KBPS = 10_000_000` (10 Gbit) — иначе сумма
остальных лимитов задушила бы безлимитного. `rate(0)` для класса тоже означает
10 Gbit и документировано в коде.

Применение идемпотентно. План (root rate, классы, фильтры) хэшируется по имени
интерфейса: если он не изменился, qdisc/классы/фильтры не трогаются вообще.
При изменении применяется diff: `class change` для изменившихся rate,
`class add/del` и `filter replace/del` только для дельты. Полное пересоздание
(`qdisc del … root` → `qdisc add … root handle 1: htb`, то же для
`handle ffff: ingress`) выполняется только при первом применении или как
fallback, если incremental-команда упала. `htb` в root не поддерживает
`replace`/`change` — это учтено.

Имя IFB — `ifb-` + 11 hex-символов FNV-1a от полного имени интерфейса
(<= 15 символов), поэтому `awg-branch-01` и `awg-branch-02` не коллизируют.

Если up-план пуст (все `up_kbps = 0`, включая чисто групповые down-лимиты),
ingress-шейпинг не нужен: worker удаляет ingress-qdisc, match-all `mirred`
и IFB. Лимит `0` означает «без ограничения». При превышении квоты тарифа
админка присылает `1 kbps` — это фактическая блокировка.

**Forwarding.** nftables-таблица `inet awg_admin`, отдельная цепь `fwd_<ifname>_<hash>`:
на каждую разрешённую пару — прямое правило `accept` и обратное
`ct state established,related accept`, затем `counter drop` для остального
внутриинтерфейсного форвардинга. Матчер входящего интерфейса —
`iifname { "<ifname>", "ifb-<hash>" }`: при ingress-шейпинге пакет приходит
уже с IFB, и без второго имени изоляция перестала бы применяться. Ответный
трафик разрешается только для уже установленных соединений, поэтому
выключение forwarding блокирует новые сессии сразу. Все правила содержат
`counter`, счётчики видны в `nft -a list chain`.

`from_ip`/`to_ip` парсятся как `IpAddr` и попадают в скрипт только в
нормализованном виде; IPv6-правила используют `ip6`. Невалидный непустой IP —
ошибка apply по интерфейсу (правило не пропускается молча); пустой IP
пропускается с логом, при этом финальный `drop` работает fail-closed. Имя
интерфейса валидируется по белому списку символов, иначе `nft`-скрипт не
строится. Таблица, цепь и правила применяются одним батчем `nft -f -`:
существование таблицы/цепи проверяется заранее, затем `flush chain` и правила,
поэтому батч идемпотентен и ошибки `add table`/`add chain` не игнорируются.

## Статистика и перезагрузка интерфейса

Счётчики читаются generic netlink-командой `WG_CMD_GET_DEVICE`. В ядре она
зарегистрирована только как dump (`.start`/`.dumpit`), поэтому запрос уходит с
`NLM_F_REQUEST | NLM_F_DUMP` и атрибутом `WG_DEVICE_IFNAME` (ядро требует ровно
один из `IFNAME`/`IFINDEX`). Ответ multipart: воркер собирает все сообщения до
`NLMSG_DONE`, объединяет пиров из всех фрагментов и выбирает устройство по имени.
Без dump-флага ядро отвечает `Operation not supported (os error 95)`.

Счётчики ядра монотонны, но обнуляются при пересоздании интерфейса или
удалении/повторном добавлении пира. Инкрементальный reconcile пиров не трогает
неизменившихся, поэтому рутинные применения состояния счётчики не сбрасывают.
Воркер хранит `CounterBook` (offset + last) в JSON-файле и при уменьшении сырого
значения добавляет предыдущее значение к offset. Наружу всегда отдаётся
монотонный тотал, поэтому админка не теряет трафик между перезагрузками,
reconcile и рестартами воркера. Каждое обнаруженное уменьшение увеличивает
внутренний счётчик `resets` (пишется в debug-лог; отдельного поля в proto
heartbeat пока нет).

Запись снапшота атомарна: временный файл, `fsync`, rename, `fsync` каталога.
Если файл повреждён, он переименовывается в `counters.json.bak`, в лог пишется
error, а воркер продолжает с нулевыми offset — данные не теряются молча.

## Проверка на живом ядре

```bash
scripts/verify-kernel.sh --apply --netns
scripts/verify-dataplane.sh --apply
sudo -E PANEL_PASSWORD=... scripts/verify-hairpin.sh --apply --group "VPN Pilot"
unshare -rn -- cargo test -p awg-worker --test live_dataplane -- --ignored --test-threads=1
```

Live-тесты `tests/live_dataplane.rs` поднимают AWG-интерфейс, гоняют ICMP через
туннель и проверяют полный путь `ReconcileService::apply/collect`: dump-статистику,
монотонные тоталы после повторного `SetDevice`, двукратное применение tc и nft.
Нужны `CAP_NET_ADMIN` (запуск под `unshare -rn`), модуль `amneziawg` и утилиты
`awg`, `tc`, `nft`.

## Запуск

```bash
docker compose --profile worker up -d --build
```

Требования: Linux с загруженным модулем `amneziawg`, `network_mode: host`,
`privileged: true`, `NET_ADMIN`, `SYS_MODULE`, смонтированный `/lib/modules`.
