# Замечания по frontend-фреймворку (silent)

Документ фиксирует проблемы, найденные при разработке AWG Admin на
`@ivlev-dev/silent` 0.7.2, и их статус после релиза 0.7.3. Приложение
обновлено до 0.7.3.

## Статус на 0.7.3

| № | Замечание | Статус |
|---|---|---|
| 1 | Динамические SVG-дети попадали в HTML-namespace | исправлено: компилятор и рантайм учитывают SVG-контекст, включая `foreignObject` и вложенные `svg` |
| 2 | `<style>` с текстовой интерполяцией ронял приложение | исправлено: raw-text биндится через `textContent`, статический CSS не экранируется, JSX-дети дают ошибку компиляции |
| 3 | `<Show>` пересоздавал детей и терял состояние форм | исправлено: ветка сохраняет DOM, пока `when` истинно |
| 4 | `.map()` в JSX не типизировался как `Child` | исправлено: `Child` принимает `Iterable<Child>` |
| 5 | Нативный `<select>` в Firefox не открывался | исправлено: `value`/`checked`/`selected` пишутся только при изменении, `event.currentTarget` корректен; открытие picker в headless остаётся ручной проверкой |
| 6 | Мелкие неудобства (`props`, `this.view`, отсутствие router/dialog/select) | `props` деструктурируются реактивно, `override` и `this.view` описаны в документации; router/dialog/select остаются прикладными компонентами |

Подробности релиза: `CHANGELOG.md` фреймворка, секция `0.7.3`
(`fix(core): svg-namespace, raw-text и реактивные props`).

## Новое замечание после 0.7.3

**7. Динамически смонтированные route-компоненты получают отдельный DI-контейнер.**

`mount("#app", App, { container })` прокидывает контейнер в корневой view, но
компоненты, которые появляются позже внутри `<Show>` (страницы роутера), при
резолве VM получают экземпляры `Router`, `Session`, `ThemeStore`, `ToastStore`
не из переданного контейнера. В результате:

- навигация из такой страницы меняет URL, но AppVM не перерисовывается;
- `Session` на странице содержит `user = null`, хотя в сайдбаре пользователь
  уже авторизован (профиль показывал «Гость» при администраторе);
- каждое открытие страницы создаёт новый `Router`.

Репро: залогиниться, открыть «Клиенты» → «Открыть»; URL меняется, содержимое
остаётся прежним до события `popstate`.

Обход в приложении: `Router`, `Session`, `ThemeStore`, `ToastStore`,
`LiveStats` сделаны process-wide синглтонами через `globalThis` (в тестах
синглтон отключён по `import.meta.env.MODE`). После этого навигация, роли и
матрица forwarding работают без перезагрузки.

Ожидание от фреймворка: контейнер из `mount` должен наследоваться всеми
динамически созданными view, либо `createComponent` внутри `Show` должен
получать `container` из текущего `ComponentContext`.

## Что осталось в приложении осознанно

- Иконки — отдельные функциональные компоненты со статическим `<svg>`
  (`src/components/icons/`). Это требование к дизайну, а не обход.
- `Select`, `Modal`, `Router` — собственные UI-компоненты панели.
- `Icon` остаётся диспетчером «имя → компонент»; динамическая вставка SVG
  больше не требуется.

## История

Первоначальные репро и гипотезы сохранены в git-истории документа. Перед
обновлением на 0.7.3 они воспроизводились на 0.7.2; после обновления
`pnpm typecheck`, `pnpm test` (406 тестов) и `pnpm build` проходят, SVG
рендерятся в правильном namespace.
