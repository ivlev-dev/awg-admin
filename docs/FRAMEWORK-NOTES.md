# Замечания по frontend-фреймворку (silent)

Документ фиксирует проблемы, найденные при разработке AWG Admin на
`@ivlev-dev/silent` 0.7.2, и их статус после релиза 0.7.3. Приложение
обновлено до 0.7.3.

## Статус на 0.7.3

| № | Замечание | Статус |
|---|---|---|
| 1 | Динамические SVG-дети попадали в HTML-namespace | исправлено: компилятор и рантайм учитывают SVG-контекст, включая `foreignObject` и вложенные `svg` |
| 2 | `<style>` с текстовой интерполяцией ронял приложение | исправлено: raw-text биндится через `textContent`, статический CSS не экранируется, JSX-дети дают ошибку компиляции |
| 3 | `<Show>` пересоздавал детей и терял состояние форм | исправлено: ветка сохраняет DOM, пока `when` истинно |
| 4 | `.map()` в JSX не типизировался как `Child` | исправлено: `Child` принимает `Iterable<Child>` |
| 5 | Нативный `<select>` в Firefox не открывался | исправлено: `value`/`checked`/`selected` пишутся только при изменении, `event.currentTarget` корректен; открытие picker в headless остаётся ручной проверкой |
| 6 | Мелкие неудобства (`props`, `this.view`, отсутствие router/dialog/select) | `props` деструктурируются реактивно, `override` и `this.view` описаны в документации; router/dialog/select остаются прикладными компонентами |

Подробности релиза: `CHANGELOG.md` фреймворка, секция `0.7.3`
(`fix(core): svg-namespace, raw-text и реактивные props`).

## 7. DI-скоуп в динамических route-компонентах (исправлено в 0.7.5)

В 0.7.3 компоненты, появлявшиеся внутри `<Show>` после `mount`, получали
экземпляры `Router`, `Session`, `ThemeStore`, `ToastStore` не из контейнера,
переданного в `mount`. Симптомы: навигация меняла URL без перерисовки, профиль
показывал «Гость» при авторизованном администраторе.

В 0.7.5 наследование runtime options и DI scope переведено на owner-контекст;
после обновления проблема не воспроизводится. Временный обход с
process-wide синглтонами удалён.

## Ограничения 0.7.5, найденные при рефакторинге

**8. DI-индекс не разрешает alias `@/` для type-импортов.**
Если интерфейс репозитория/сервиса импортирован в конструктор как
`import type { X } from "@/..."`, сканер индекса не находит реализацию и
сборка падает с `MISSING_EXPORT`. Приходится использовать относительные пути
(`../../application/...`). Ожидание: индекс должен разрешать `paths`/`alias`
так же, как Vite.

**9. `lazy` + `Suspense` внутри `Show` оставлял осиротевший DOM.**
`Suspense` — многокорневой компонент, поэтому `createComponentLight` не вешает
disposer на его узлы, а `Show` запоминает узлы до асинхронной замены
fallback→контент. При переходе старая страница остаётся в DOM. Обход:
обёртка `PageSlot` с единственным корнем вокруг `Suspense`. Ещё одно
ограничение: после ошибки `lazy` не умеет сбрасывать `loaded/loading` —
«Повторить» реализовано через перезагрузку страницы.

**10. Шум `NotFoundError` при первом рендере lazy-страницы.**
При прямом заходе на ленивый маршрут (например, `/stats`) в консоль один раз
попадает `console.error` с `NotFoundError` и стеком
`component-lite → render → Icon`. Страница при этом отображается корректно.
Похоже на попытку `Suspense`/`Show` адоптировать узел до появления контента;
на функциональность не влияет, но засоряет консоль.

## Что осталось в приложении осознанно

- Иконки — отдельные функциональные компоненты со статическим `<svg>`
  (`src/components/icons/`). Это требование к дизайну, а не обход.
- `Select`, `Modal`, `Router` — собственные UI-компоненты панели.
- `Icon` остаётся диспетчером «имя → компонент»; динамическая вставка SVG
  больше не требуется.

Первоначальные репро и гипотезы сохранены в git-истории документа. Перед

рендерятся в правильном namespace.
